# 按键驱动程序

## 一、APP和驱动之间的联动

### 1.1 驱动的基本技能：

- 中断
- 休眠
- 唤醒
- poll



### 1.2 APP的基本技能

- 阻塞
- 非阻塞
- 休眠
- 异步通知



### 1.3 APP获取按键状态的四种方式

- 查询方式：APP时不时地读取一下按键的状态
- 休眠-唤醒方式：APP阻塞地读取按键状态，依靠中断来唤醒；
- poll方式：约定一个等待的时间，在这段时间内休眠等待数据，过时退出等待；如果有数据，则紧接着调用read去读数据，如果时间到了仍旧没有数据则报超时；
- 异步通知：APP通过fasync向驱动程序提供自己的PID等信息，然后可以去做别的事情，驱动程序在获取到数据之后，再通过PID通知到该APP；



#### 1.4 驱动程序开发原则

驱动程序**只提供能力，不提供策略**，具体的使用场景和顺序由APP自行决定；

### 2.1 使用原因

原来通过控制寄存器来操作GPIO pin脚的方式非常低效，每款芯片都有自己的GPIO控制系统：

![image-20250512231520904](E:\embedded_learning\embedded_driver_code_management\src\005_button_drv\image-20250512231520904.png)

两个特征：

- 引脚复用
- 引脚配置







### 2.2 pinctrl在设备树中的语法

```dtd
device_node {
    pinctrl-names = "default", "sleep";  // 状态名称
    pinctrl-0 = <&pinctrl_config_default>;  // 默认状态
    pinctrl-1 = <&pinctrl_config_sleep>;   // 睡眠状态
    // 其他设备属性...
};

```

- **`pinctrl-names`**：定义配置状态的名称（如 `default`、`sleep` 等）。
- **`pinctrl-<n>`**：引用具体的 pinctrl 配置（指向pinctrl子节点）。



pincontroller子节点示例：

```dtd
state_0_node_a {
	uart0 {
		function = "uart0";
		groups = "u0rxtx", "u0rtscts";
	};
};
state_1_node_a {
	spi0 {
		function = "spi0";
		groups = "spi0pins";
	};
};
state_2_node_a {
	function = "i2c0";
	pins = "mfio29", "mfio30";
};
```

pincontroller子节点的格式不是统一的，虽然格式都不统一，但是其中的内容都是围绕指定group、function和pin脚的配置



## 三、GPIO子系统

### 3.1 为什么要使用GPIO子系统

要操作 GPIO 引脚，先把所用引脚配置为 GPIO 功能，这通过 Pinctrl 子系统来实现。

然后就可以根据设置引脚方向(输入还是输出)、读值──获得电平状态，写值──输出高低电平。

以前我们通过寄存器来操作 GPIO 引脚，即使 LED 驱动程序，对于不同的板子它的代码也完全不同。

当 BSP 工程师实现了 GPIO 子系统后，我们就可以：

- 在设备树里指定 GPIO 引脚

- 在驱动代码中：使用 GPIO 子系统的标准函数获得 GPIO、设置 GPIO 方向、

读取/设置 GPIO 值。

这样的驱动代码，将是单板无关的。



### 3.2 如何在设备树中指定引脚

在设备树中，“GPIO 组”就是一个 GPIO Controller，这通常都由芯片厂家设置好。我们要做的是找到它名字，比如“gpio1”，然后指定要用它里面的哪个引脚，比如**<&gpio1 0>**。

以下是一些设备树代码：

![image-20250513164255306](E:\embedded_learning\embedded_driver_code_management\src\005_button_drv\image-20250513164255306.png)

目前只需要关注其中的两个属性：

```dtd
gpio-controller;
#gpio-cells = <2>;
```

- “gpio-controller”表示这个节点是一个 GPIO Controller，它下面有

很多引脚。

- “#gpio-cells = <2>”表示这个控制器下每一个引脚要用 2 个 32 位的数(cell)来描述。

普遍的用法是，用第 1 个 cell 来表示哪一个引脚，用第 2 个 cell 来表示有效电平：

```
GPIO_ACTIVE_HIGH ： 高电平有效
GPIO_ACTIVE_LOW : 低电平有效
```

int gpiod_direction_input(struct gpio_desc *desc);
